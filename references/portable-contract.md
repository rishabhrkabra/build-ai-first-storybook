# Portable contract v2

Read this when scaffolding, validating, publishing or upgrading the machine interface.
Requires Python 3.9+; repository-policy checks also require Git. These dependency-free
scripts do not install Storybook, implement framework scanners, or run browser tests.

## One authoring source, separate distribution

`ai-design-system/` is **private authoring data**, outside every Storybook `staticDirs`,
application public directory and deployment root. It contains inventory, candidates,
owner receipts, source authority and decisions. A `publication: private` JSON field
does not provide access control. Do not copy this directory to a web server.

The authoring manifest maps required artifacts. Keep `public-api.json` and
`context-index.json` as the sole authoring registries. They may include `review`
records, but only `ready` records can enter the generated selectable catalogue.
Do not also maintain `catalog.json`, `current.json` or `context/index.json` here.
Those are **generated outputs**, not second registries. Migration/evidence sidecars
are project-local and private; their filenames are not a new universal schema.

Configure:

```json
{
  "frameworks": ["react"],
  "distribution": {
    "access": "local-only",
    "basePath": "/storybook/ai",
    "files": []
  },
  "repositoryPolicy": {
    "configured": false,
    "sourceRoots": [],
    "sharedRoots": [],
    "storyRoots": [],
    "storyIndex": "",
    "exportsManifest": ""
  }
}
```

These are illustrative settings, not framework or URL requirements. Choose supported
framework identifiers consistently with component records. `access` also accepts
`authenticated` and `public`; it labels the intended mode, **does not configure auth**.
Apply hosting access controls and verify them separately. A private package/local
interface is legitimate; public source hosting is not a prerequisite for a good DS.

## Three different checks

1. `validate.py --root PROJECT` checks schema, relationships, exact required-file
   checksums, dates, expiry, receipt structure and referenced files. For declared-ready
   records it checks actual story IDs and presence of test/gate evidence. This is
   **not** evidence that tests passed, approvals are authentic, or visuals are correct.
2. Add `--base-ref FULL_BASE_SHA` for configured repository policy: compare against
   a trusted ancestor selected by protected CI, not by the proposal. Reject baseline
   rewrites, scan-scope changes, rewritten receipts, unapproved additions/removals,
   contract/deprecation changes, shared files, new story files and newly published
   story IDs. Check a generated export observation against current source hashes.
3. Real CI must build/import the package, run framework-aware ownership analysis,
   interactions, accessibility, responsive/visual review and consumer checks. Bind
   receipts to the actual source revision and built artifact digest. Run the policy
   adapter in that protected job; never trust a hand-written export observation.

The checker deliberately reports `runtimeAndVisualAcceptance: not-executed-by-this-checker`
and `approvalAuthenticity: requires-protected-review`. A JSON owner name or `passed`
flag is not a signature. Protect workflow/checker code, approval changes and the merge
base with the repository's real review/branch rules. Do not treat this script as an
adversarial sandbox or claim that generic path scans find arbitrary semantic clones.

### Configure repository policy once

Inspect the target framework, package entrypoints, aliases, lazy imports, registries,
dynamic stories and downstream packages. Configure exhaustive roots for that scope.
`sharedRoots` controls admission into shared source, `storyRoots` the published story
sources, and `sourceRoots` the input set for export freshness. Review and land this
configuration and an observed freeze line separately before enforcing it against a
trusted base. Existing debt is observed, not endorsed. Later scope changes require
separate policy review; do not edit a proposal's baseline to make its check green.

`storyIndex` points to the actual built Storybook `index.json`. Published IDs not in
the trusted freeze line need `storyApprovals`, including IDs added to an existing
file. Approve docs as docs, not as reusable component exports. A project adapter
must account for custom story generators and verify that this index belongs to the
current build; the portable checker cannot prove build provenance by itself.

`exportsManifest` is generated by the target framework's export/package adapter:

```json
{
  "revision": "FULL_SOURCE_REVISION",
  "sourceDigest": "SHA256_OF_SORTED_SOURCE_PATH_TO_FILE_HASH_OBJECT",
  "exports": [{"componentId": "button", "importPath": "@example/ui/button"}]
}
```

Use `contract_io.object_sha(policy.source_files(root, sourceRoots))` for the digest.
Each observed public component export maps exactly once to an approved API ID and
import path. Selectors, tokens and non-component exports need an explicit adapter
classification, not fake component records. Regenerate the observation; do not
repair it by editing the reported export list. A clean release job also verifies
source files against the recorded commit and the built output's actual hash.

### Approval receipts

All receipts need a unique `id`, named `owner`, timezone-aware ISO `approvedAt`, and
nonempty repo-relative evidence-file paths (`consumerEvidence` for retirement).
Receipts already in the trusted base are append-only. Multiple decisions can target
the same component; give every decision its own ID and exact reviewed scope.

| Collection | Additional required fields |
|---|---|
| `promotionApprovals` | `componentId`, `candidateId`, exact full `candidateSnapshot` in review status |
| `sharedPlacementApprovals` | `path`, screen-agnostic `semanticScope` |
| `storyApprovals` | `path`, nonempty explicit `storyIds`, `decision: publish-story` |
| `contractApprovals` | `componentId`, `contractSha256`, `decision: change-contract` |
| `deprecationApprovals` | `componentId`, `decision: deprecate` |
| `retirementApprovals` | `componentId`, `decision: retire`, reachability evidence |

Use `object_sha(policy.contract_payload(component))` for the contract digest; it
excludes verification receipts so rerunning tests is not itself an API change.
Keep approved candidate records immutable to retain their exact snapshot; propose
a new revision with a new candidate ID. A rejected candidate cannot be promoted by
adding an empty snapshot. Recurrence opens review only. Zero observed usage does not
authorize deprecation or deletion. Withdrawal/revocation needs an explicit owner
decision and corresponding lifecycle/replacement changes, not erasing old receipts.

Declared-ready records need nonempty source, stories, docs, tests, authority and
measurable state/behavior/responsive/accessibility/composition contracts. `styles`
and `types` are arrays (empty is legitimate if no separate artifacts are required).
`verification` records the release revision, built artifact SHA256 and `checks` for
build, interaction, accessibility, responsive, visual and consumer evidence. A truly
inapplicable interaction can be a reviewed passing applicability check with rationale;
missing infrastructure must never be relabelled as not applicable.

## Safe export

`export_public.py --root PROJECT --output FRESH_DIRECTORY --base-ref FULL_BASE_SHA`
generates a candidate release, **never deploys it**. Without a trusted base it can
generate an empty, non-selectable preview only. Existing output is refused to prevent
stale-file carryover. Use a fresh build directory, inspect it, then release atomically
through the project's normal approved workflow.

Every distributable needs an explicit mapping in `distribution.files`:

```json
{
  "source": "packages/ui/src/Button.tsx",
  "target": "source/Button.tsx",
  "owner": "ACTUAL_REVIEWER",
  "approvedAt": "ACTUAL_ISO_TIMESTAMP",
  "sha256": "EXACT_FILE_SHA256"
}
```

Ready catalogues also need `distribution.catalogApproval` with `owner`, `approvedAt`
and `sha256: object_sha(publicApiObject)`, because component names, contracts and
examples can themselves disclose private data. Never manufacture owner approval.
Raw private candidate/lifecycle/inventory/decision/manifest registries cannot be
mapped, even under another filename. Explicitly review source, CSS, types, assets,
fonts, docs and optional token/rule/recipe files for secrets, licensing and product
data. The exporter is not a general secret or content classifier.

Exported files are only: reviewed mappings; ready-only generated `catalog.json`;
`context/index.json`; `context/<id>.json`; `llms.txt`; and `current.json`. The latter
advertises only generated endpoints, with checksums for every file except itself.
It does not expose private approval paths or raw review context. Regenerate contexts
from the approved public API; never copy the private context index.

Mount **only this fresh export** at `distribution.basePath`. Test actual HTTP URLs
under that path, checksums and access controls, and negative requests for private
canary files. Inspect the complete Storybook build too: story bundles/MDX/staticDirs
can leak private evidence independently of the `/ai` export. Deleting a sidebar label
does not remove files from publication. Consult the installed Storybook version's
[static directory rules](https://storybook.js.org/docs/api/main-config/main-config-static-dirs).

## Explicit v1 upgrade and installed copies

Do not run a new scaffold over an existing registry. Preserve a local backup, record
its revision, and migrate to v2 in a reviewable change. Carry forward inventories,
decisions and provenance without inventing approvals. Preserve each existing status;
if supporting evidence is missing, mark the record for review rather than silently
declaring it ready. Add the v2 distribution/policy fields, required approval arrays,
framework bindings and receipt contracts. Rename the old `selfContainedHostedInterface`
and `stableBaseUrl` safeguards to `selfContainedInterface` and `stableEntryPoint`;
authorized local/package use must not imply public hosting. Reconcile any author-maintained
`catalog.json`/`current.json`/`context/index.json` into the canonical authoring source,
archive the originals privately, and remove the competing active files. Do not copy
those former public files into the new output as a shortcut.

Refresh exact authoring checksums, run metadata checks, then establish the separately
reviewed v2 policy baseline. No script auto-approves grandfathered components. Run
the real integration gates before publishing ready records. Choose one editable skill
source; compare and sync installed mirrors explicitly, preserving any unique content
before removal. A changed schema or stale copy is an actionable upgrade, not something
to suppress in the validator.

## Regression coverage and limits

Run `python3 scripts/test_contract.py`. Fixtures use synthetic local repos, approvals
and gate receipts; they test checker behavior and exported files, not the trustworthiness
of a real reviewer or a real app's rendering. Add target-framework adapters and browser
tests in each adopting project. Offline checks cannot certify any real product
without executing its actual contracts and builds.
